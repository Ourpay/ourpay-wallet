Tool names below are canonical; a host may add its own server prefix or shorten display labels. Inspect the connected server’s `tools/list` after updates. A catalog entry documents an interface, not an assertion that a deployment enables every route or that a call has been executed.

Start with `ourpay_wallet_guide` using `{"topic":"overview"}`, then read `ourpay_wallet`. See [workflows](WORKFLOWS.md), [protocol limits](PROTOCOLS.md) and [troubleshooting](TROUBLESHOOTING.md) before executing a new type of action.

## How to read this reference

- Required fields must be supplied. An optional field without a schema default can still have backend defaults or policy constraints; omission does not mean unlimited.
- On-chain amounts use integer base-unit strings. Hyperliquid size/price use human-unit decimal strings. See the units table in [WORKFLOWS.md](WORKFLOWS.md#amounts-and-identifiers).
- MCP annotations are host hints, not authorization. A stateful quote can be marked non-read-only while moving no funds. Owner settings, exact intent, backend policy and host permissions still apply.
- Results are MCP `content` blocks, normally with JSON in the text block. Check `isError` and the operation status. A successful tool invocation is not proof of settlement.
- This reference captures input schemas and tool descriptions. Returned resource fields are described in the workflow guides and SDK TypeScript interfaces. Do not assume an undeclared output schema.

### `ourpay_wallet`

Open the wallet linked to the owner’s OurPay account. If setup_url is present, show it for the owner to sign in and authorize this agent once. ChatGPT, Claude and other agents use the same wallet when linked to the same account. A connection cannot create an anonymous wallet. With Risky mode off, payments and trades return an approval ID and email the owner before execution; follow ourpay_wallet_approval. Supported actions execute without per-action approval in Risky mode. The returned spending settings show the shared daily USD budget (default $10,000, reset at 00:00 UTC) and Risky mode. Only the owner can raise limits or enable Risky mode in the wallet page. Never ask for, read, or store the recovery phrase; OurPay stores an encrypted backup and account login restores access.

**MCP annotations:** readOnlyHint=false, destructiveHint=false, idempotentHint=true, openWorldHint=false.
